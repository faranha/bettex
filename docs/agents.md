# Alpha agents and execution boundaries

The canonical details remain in [agent-hierarchy.md](agent-hierarchy.md),
[architecture.md](architecture.md), [trading-policies.md](trading-policies.md),
and [treasury-governance.md](treasury-governance.md). The current observation
services and their UI are documented in [agents-operations.md](agents-operations.md);
contextual and technical helpers are documented in [helpers.md](helpers.md).
Repository preparation
does not change the existing agent/subagent architecture.

The first operationally structured alpha branch is **BETTEX → prediction market
coordinator → BTC, ETH and SOL specialists**. Existing sports, trading and
prediction identities on the public site are product presentation, not evidence
that every financial provider is connected.

The dashboard now exposes 13 deterministic observation/control services,
including real Allora BTC/ETH/SOL inputs and public sports-event discovery.
Crypto/meme coins and bonus run readiness diagnostics with no configured
provider inputs. These persisted procedures do not establish 13 calibrated
financial strategies, language-model agents or authorized execution connectors.

The treasury/governance capability observes and proposes control actions. It is
not an opportunity-seeking competitor to the specialists. Allora, market books
and oracles are tools/data sources, not new hierarchical agents.

Mandatory financial flow:

**Agent proposal → deterministic risk authorization → executor →
reconciliation → accounting evidence.**

No agent receives private keys or signing privileges. Policy versions, budgets,
permissions and audit events are deterministic and durable. Unavailable model,
cost, freshness or authorization evidence blocks the affected proposal.

Local contract tests and paper-order fixtures exercise engineering controls.
They do not demonstrate calibrated predictive advantage, external trading
fills, profit, institutional governance or production custody. Policy
publication/approval/activation and existing integration blockers remain
explicit; Git synchronization cannot authorize them.
